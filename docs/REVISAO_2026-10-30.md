# Revisão técnica — 30/10/2026

Escopo: somente Desenvolvimento_do_Jogo. Código, persistência, navegação,
consumíveis, ferramentas de execução, testes e documentação. Nenhum salvamento
pessoal foi usado ou alterado. Não foi publicada uma release.

## Problemas corrigidos

| Problema | Correção |
|---|---|
| Uso de item sem estoque lançava NameError ao desenhar o aviso | Importação explícita de RED; teste por clique para H e T |
| Primeiro cadastro podia contornar a confirmação de nova partida | Cadastro retorna ao fluxo que verifica se existe partida |
| H/T podiam ser atribuídas a outras ações | Teclas reservadas também na leitura das preferências |
| Nome inválido salvo podia dispensar cadastro e impedir pontuação | Mesma validação de nome aplicada às preferências |
| Seleção de consumível sobrevivia à troca de partida | Seleção limpa ao sair, iniciar e retomar |
| Uso direto de consumível ignorava pausa/fim | Verificação de accepts_actions no ponto de aplicação |
| Falha ao registrar pontuação era ocultada pelo salvamento do snapshot | checkpoint conserva o snapshot e retorna a falha ao chamador |
| Ranking não oferecia navegação por teclado | Foco e ativação dos botões com Tab/setas/Enter |
| Descrição da cura não correspondia ao cálculo | Texto alinhado à vida máxima, mínimo 25 e limite de vida |
| Loja não explicava como usar itens na batalha | Instrução H/T, clique e cancelamento na tela |
| Testes e roteiro de regressão pulavam perfil ou usavam posições antigas do menu | Fixtures isoladas, navegação pelo rótulo e cadastro real no ensaio |
| CRIAR_EXE.bat era mencionado, mas não existia | Script de instalação das dependências e build com testes |
| JOGAR.bat do pacote exigia uma .venv não distribuída | Pacote sem main.py executa o EXE; fontes usam a .venv |
| Preparador aceitava .venv de outra versão | Checagem explícita de Python 3.12 e NumPy |
| README afirmava estabilidade/GPU padrão/Python 3.10+ | Documentado estágio Alfa, software padrão e Python 3.12 |

A retomada com o perfil ativo é um comportamento deliberado, documentado em
um teste anterior. Essa regra foi preservada; resultados já gravados continuam
idempotentes. Os testes novos verificam tanto a retomada em memória quanto em disco.

uma construção real do executável.

O interpretador utilizado é Python 3.12.14 com pygame-ce 2.5.8, proveniente do
ambiente já disponível em Sodados_vs_Zumbis/.venv. Esse ambiente foi apenas
utilizado; o código executado e os relatórios pertencem a Desenvolvimento_do_Jogo.
A instalação de uma .venv própria permanece disponível pelo preparador.

## Limites

Testes headless não comprovam áudio real, drivers OpenGL, tela cheia ou experiência
manual de uma partida completa. Não foi gerado nem validado novo executável nesta
revisão. Os scripts de Windows precisam de Python Launcher/Python 3.12 no ambiente
do usuário. Os consumíveis são gravados no SQLite e o estado da batalha em JSON;
essas duas gravações não constituem uma única transação entre arquivos. Uma
interrupção abrupta entre elas pode perder o efeito de um item já descontado.
